# Ghost FTP 0.1.5 Beta

Ghost FTP 0.1.5 Beta is a quality, parser-hardening and workstation-efficiency release for the native Windows/Linux FTP/FTPS client. It builds on the 0.1.4 protocol/shutdown work without expanding platform or protocol claims.

## Summary

This release focuses on four practical areas: safer processing of untrusted directory listings, lower transfer/UI overhead under fast or batched workloads, more complete persisted workstation layout state, and stronger deterministic regression coverage.

The supported protocol set remains FTP, Explicit FTPS and Implicit FTPS. Windows and Linux remain the only shipping application targets. The application remains telemetry-free and shipping projects retain zero third-party NuGet `PackageReference` dependencies.

## New

- Added deterministic settings backup/recovery regression coverage, including bounds for persisted window, splitter, retry and concurrency state.
- Added deterministic LIST/MLSD parser-hardening coverage for oversized lines, excessive MLSD facts and safe Unix symlink-name handling.
- Added deterministic EPSV coverage using a valid non-default delimiter.
- Added malformed PASV tuple rejection coverage before any data connection can be established.
- Added a visible **Pause queue / Resume queue** action directly to the Windows Transfers header while preserving the truthful dispatch-pause semantics introduced in 0.1.3.
- Added persistence for the Windows saved-server sidebar width and Connection Log / Quick Connect panel height.

## Improved

### FTP listing parser

- LIST and MLSD parsing now bounds individual listing lines to 64 KiB.
- MLSD fact processing is limited per entry so a pathological server response cannot create unbounded per-entry parser work.
- Unix and Windows LIST regexes use the .NET non-backtracking regex engine.
- Listing input is enumerated incrementally with `StringReader` rather than creating a second full split/copy of the listing payload.
- Unix symlink entries strip the ` -> target` metadata before remote-name validation. This keeps a safe link name visible even when the server reports an absolute target, while symlinks remain non-directory entries and are not recursively followed.

### Transfer memory and UI efficiency

- FTP send/receive data paths rent 128 KiB buffers from `ArrayPool<byte>` instead of allocating a new large managed buffer for each data stream.
- Rented transfer buffers are cleared before they are returned to the shared pool because they may contain private file data.
- Transfer progress is delivered through an inline `IProgress<T>` adapter so the worker does not add an unnecessary ThreadPool dispatch before the renderer marshaling boundary.
- Renderer progress updates are throttled to approximately 10 Hz during active transfers while final completion state remains immediate.
- Redundant terminal `JobUpdated` notifications were removed.
- Burst transfer completions are coalesced into one delayed Local/Remote refresh rather than issuing one FTP LIST for every completed file.

### Workstation layout

- The first-run Connection Log / Quick Connect area is more compact, leaving more vertical space for Local and Remote file panes.
- Sidebar width, connection-panel height, transfer-panel height, Local/Remote ratio and window dimensions are now persisted together.
- Restored layout values are bounded before use.
- Queue pause state is synchronized between the visible Transfers header action and its context-menu action after asynchronous startup.

## Fixed

- Fixed unnecessary duplicate completion notifications that could cause repeated renderer work after each transfer.
- Fixed repeated post-transfer remote refresh behavior during fast batches.
- Fixed safe Unix symlink LIST entries being discarded when their reported target used an absolute path.
- Fixed incomplete persistence of user-adjusted Windows workstation split dimensions.
- Fixed the Windows queue-pause action being discoverable only through the transfer context menu/header variants rather than having a clear primary header control.

## Security

- Listing parsing now places additional CPU/resource bounds around server-controlled LIST/MLSD text.
- Non-backtracking regexes reduce regex backtracking risk on hostile or malformed listing lines.
- Strict EPSV/PASV parsing from 0.1.4 is retained and covered by additional malformed/alternate-delimiter tests.
- Passive data sockets remain tied to the authenticated control host rather than trusting PASV host redirection.
- Transfer buffers containing user file data are cleared before returning to the shared pool.
- Existing fail-closed security-mode validation, TLS certificate/hostname validation, `AUTH TLS`, `PBSZ 0`, `PROT P`, required `TYPE I`, command-injection guards, traversal bounds and root-delete protections remain unchanged.

## Privacy

- No application telemetry, analytics, advertising, fingerprinting, cloud profile sync, hidden crash upload or account requirement was added.
- Transfer-buffer pooling is entirely local; buffers are explicitly cleared before reuse.
- Quick Connect remains session-only unless the user explicitly saves a site.
- Saved credentials remain opt-in and platform-local: current-user DPAPI on Windows, AES-256-GCM with local user-private key material on Linux.

## Stability and performance

- Reduced large-object/GC pressure during file transfers by reusing bounded pooled buffers.
- Reduced ThreadPool scheduling and renderer churn from high-frequency transfer progress callbacks.
- Reduced remote control-channel work after batch completion by debouncing repeated refresh requests.
- Settings recovery continues to use atomic replacement plus a bounded backup fallback and is now explicitly regression-tested with corrupted primary data.
- Concurrent session and queue disposal regressions from 0.1.4 remain part of the hardening suite.

## UI / UX

- Windows authentic reference capture retains the professional dark dual-pane workstation while using a shorter connection area and more space for the file panes.
- Transfers now expose Pause queue / Resume queue beside retry/cancel/cleanup actions.
- The pause label remains truthful: running transfers continue; only new queued/retrying dispatch waits.
- Site Manager keeps the dark segmented General/Advanced design introduced in the previous polish work.

## Windows Setup and packaging

- Setup/Portable packaging architecture is unchanged: one maintained `GhostFTP-Setup.exe` handles install/update/uninstall registration; no separate `uninstall.exe` is generated.
- Version metadata advances to 0.1.5 / 0.1.5.0 / 0.1.5-beta.
- Windows x64/ARM64 Setup and Portable assets remain verified by CI before publication.
- Stable-signing requirements remain reserved for the stable release policy; Beta signing state is reported by the release workflow without overstating trust.

## Linux

- The native C# X11/XWayland renderer continues to share the same Core protocol, transfer queue, settings, localization and security behavior.
- The parser, pooled data buffers, progress-delivery improvements, settings bounds and expanded hardening tests are shared cross-platform where applicable.
- Linux x64/ARM64 self-contained packages and checksum/runtime verification remain release gates.

## Localization

- The local 29-language catalog remains available with English (`en`) as primary/default/fallback.
- No online translation service was introduced.
- Existing Croatian queue-management translations and English safety fallback remain in place.

## Internal engineering notes

- Transfer progress now has one explicit renderer-marshaling boundary rather than an implicit `Progress<T>` ThreadPool hop followed by UI marshaling.
- Final transfer states are authoritative notifications; cleanup no longer emits an additional no-op job notification.
- Post-completion pane refresh uses a short cancellation-based debounce and is cancelled during window shutdown.
- Persisted layout dimensions are normalized in the same bounded settings layer used for concurrency/timeouts.

## Known limitations / upgrade notes

- Ghost FTP 0.1.5 remains Beta.
- SFTP/SSH is not implemented and is not represented as FTP/FTPS support.
- Queue pause does not freeze an already-running FTP byte stream.
- Linux uses the system X11/XWayland environment and `libX11.so.6` ABI.
- Existing local profiles/settings remain compatible; newly persisted layout fields have safe defaults when absent.
- Android, iOS, macOS/MacCatalyst and a browser client are not shipping targets in this repository line.
