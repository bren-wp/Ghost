# Ghost FTP 0.1.4 Beta

Release channel: **Beta**  
Public version: **0.1.4**  
Informational version: **0.1.4-beta**  
Platforms: **Windows x64/ARM64 and Linux x64/ARM64**

Ghost FTP 0.1.4 Beta is a protocol-hardening and stability release. It keeps the 0.1.3 workstation, transfer-management and Setup improvements while tightening FTP reply handling, passive-mode parsing and asynchronous shutdown behavior in the shared Core used by both desktop platforms.

## Stability and lifecycle hardening

### Race-safe FTP session shutdown

`FtpSession.DisposeAsync()` now has a single coordinated shutdown owner. Concurrent disposal callers wait for the same completion signal instead of racing transport cleanup or disposing the session gate underneath another waiter.

The resulting lifecycle contract is deterministic:

- disposal is idempotent;
- concurrent disposal callers complete together;
- new operations are rejected once shutdown begins;
- transport state is reset once;
- semaphore disposal races are avoided;
- disconnect remains safe when disposal is already in progress.

### Race-safe transfer queue shutdown

`TransferQueueService` now coordinates shutdown with the same single-owner pattern. The queue completes its writer, releases paused dispatch waiters, cancels active work, waits for workers, and only then disposes remaining cancellation resources.

Enqueue attempts made after shutdown begins fail cleanly instead of being accepted into a queue that can no longer dispatch them.

## FTP protocol compatibility and hardening

### Bounded preliminary greeting support

Some valid FTP servers send a preliminary `1xx` greeting such as `120` before their final `220` service-ready reply. Ghost FTP now accepts a bounded preliminary greeting sequence and requires a final positive-completion greeting. The sequence is capped so a server cannot keep the client in an unbounded greeting loop.

### Stricter control-reply framing

FTP control replies now require:

- a numeric reply code in the `100..599` range;
- a standards-compatible fourth character (`space` or `-`) when present;
- bounded reply-line length;
- bounded multiline reply count;
- bounded total multiline character count;
- existing command timeout/cancellation behavior.

Malformed framing such as `220X ...` is rejected rather than being interpreted as a valid `220` greeting.

### Strict EPSV/PASV parsing

Passive-mode parsing was rewritten to remove permissive digit extraction.

- EPSV validates delimiter framing and the final port range.
- PASV reads exactly the six comma-separated tuple values inside the passive response, validates every value as `0..255`, and computes the data port only from `p1,p2`.
- Trailing numeric diagnostics or other unrelated numbers can no longer change the selected data port.
- The data connection remains intentionally tied to the authenticated control host; Ghost FTP does not trust a PASV-supplied host for redirection.

This preserves interoperability while keeping the existing FTP bounce/redirection defense.

## Deterministic hardening regression suite

A new package-free `GhostFTP.HardeningSelfTest` project runs locally in CI on **both Windows and Linux**. It does not depend on an Internet FTP service.

The suite currently verifies:

1. concurrent `FtpSession.DisposeAsync()` idempotence and post-disposal rejection;
2. concurrent `TransferQueueService.DisposeAsync()` idempotence and post-shutdown enqueue rejection;
3. rejection of malformed FTP reply framing;
4. real loopback FTP control/data interaction using a `120 -> 220` greeting and a PASV response containing trailing numeric diagnostics.

The loopback fake server exercises USER/PASS, PWD, TYPE I, EPSV fallback, PASV, LIST, the real passive data connection and QUIT. This gives the release pipeline a deterministic protocol-compatibility gate rather than relying only on static source inspection.

## Existing workstation behavior retained

0.1.4 retains the 0.1.3 desktop improvements, including:

- dual-pane Local/Remote workstation workflow;
- resizable Windows panes and transfer area;
- Site Manager and session-only Quick Connect;
- bounded parallel transfer queue;
- queue dispatch pause/resume;
- retry, cancellation and selective history cleanup controls;
- upload/download progress, throughput and state reporting;
- Windows x64/ARM64 Setup and Portable packages;
- Linux x64/ARM64 native X11/XWayland packages;
- 29 selectable local languages with English as the default/fallback;
- authentic compiled Windows UI capture in CI.

## Security and privacy contract

The release continues to enforce:

- explicit FTP / Explicit FTPS / Implicit FTPS mode selection;
- TLS 1.2/1.3 with certificate and hostname validation;
- no silent FTPS-to-FTP downgrade;
- `PBSZ 0` and `PROT P` for encrypted FTPS data channels;
- binary `TYPE I` transfers;
- CR/LF/NUL command-injection rejection;
- passive data channels bound to the authenticated control host;
- bounded control replies, directory listings, traversal and queue capacity;
- local path containment protections;
- cancellation-aware transfer cleanup;
- local-only profile/settings persistence;
- current-user DPAPI password protection on Windows;
- AES-256-GCM local password protection on Linux;
- no application telemetry, advertising SDK, cloud profile synchronization or hidden crash uploader;
- zero third-party NuGet `PackageReference` dependencies in shipping/test projects.
