# Ghost FTP 1.6.0

Release date: 2026-09-05

Ghost FTP 1.6.0 is a connection-resilience, transfer-observability and workstation-safety release. It builds on the resizable workspace and bounded parallel queue introduced in 1.5.0 without weakening the product's privacy-first, zero-NuGet and strict-FTPS design rules.

## Connection resilience and keepalive

Ghost FTP now has an explicit control-channel keepalive facility for real FTP/FTPS sessions.

- A configurable keepalive interval is available from Settings.
- `0` disables keepalive completely.
- Enabled values are restricted to 15–600 seconds.
- The default is 60 seconds.
- Keepalive sends the standard FTP `NOOP` command only to the FTP/FTPS server that the user explicitly connected to.
- Demo mode never uses keepalive and remains fully local.
- The interval can be changed while the application is running; disabling it prevents later keepalive requests without requiring a restart.
- Keepalive does not contact ghostftp.com, brendigo.com, GitHub, an analytics endpoint or any third-party service.

A failed `NOOP` now invalidates the browser control connection instead of leaving stale connected state behind. The FTP transport is reset, the Remote pane is cleared, the visible status changes to **Connection lost**, and the user can reconnect cleanly.

Connection Diagnostics received the same stale-state hardening: a genuine control-channel failure resets the unusable transport rather than allowing `IsConnected` to remain misleadingly true.

## Configurable parallel transfer limit

The parallel worker pool introduced in 1.5.0 is now user-configurable.

- Concurrent transfers can be set from 1–8.
- The default remains 3.
- The value is normalized before use when loaded from local settings.
- Each real FTP/FTPS transfer continues to receive an isolated transfer session.
- The browser connection remains separate from queued transfer connections.
- Automatic retry count remains configurable independently from concurrency.

Concurrency and automatic-retry worker configuration is created at application startup, so changes to those two settings apply after a restart. Connection timeout values apply to the next connection. Keepalive changes apply immediately.

## Richer transfer telemetry — local only

The transfer queue now exposes more useful operational information without introducing product telemetry.

Each transfer can display:

- transferred bytes and known total size;
- percentage progress;
- current transfer speed;
- estimated time remaining (ETA) when the total and current speed are known;
- retry count;
- start timestamp;
- finish timestamp;
- source and destination;
- final error text when a job fails.

The queue header also displays aggregate live throughput across running jobs.

Double-clicking a transfer now opens transfer details instead of blindly retrying it. Retry remains an explicit action for failed/cancelled jobs.

All of this information remains inside the local application process. Ghost FTP does not upload transfer metrics, file names, server information, timing information or error text.

## Resume-speed accuracy fix

Transfer speed calculation was hardened for resumed downloads and other transfers that begin reporting progress from a non-zero byte offset.

The first progress sample now establishes the speed baseline. Previously, pre-existing resumed bytes could be counted as though they had moved during the current measurement interval, temporarily inflating the displayed speed.

The revised model measures only bytes transferred between timed samples.

## Keyboard and focus safety

1.6.0 fixes an important workstation-input routing issue.

Global file-operation shortcuts are now scoped to the pane that actually owns keyboard focus.

- `F5` refreshes the active Local or Remote pane.
- `F2` renames only in the active file pane.
- `Delete` deletes only from the active Local/Remote file pane.
- When the transfer queue has focus, `Delete` cancels the selected transfer instead of falling through to a local-file delete action.
- `Ctrl+A` selects all items in the active Local, Remote or Transfers list.
- `Enter` opens the selected local folder or activates the selected remote item.
- `Backspace` navigates to the parent directory in the active file pane.
- `Ctrl+F` and `Ctrl+L` now act only when a Local/Remote file pane is actually active.

This removes ambiguous fallback behavior where queue/sidebar focus could previously route destructive keyboard commands to the Local pane.

## Settings and persistence hardening

New reliability settings are local-only and pass through the existing bounded settings store.

- Concurrent transfers are normalized to 1–8.
- Keepalive is normalized to disabled (`0`) or 15–600 seconds.
- Existing connect, command and transfer-idle timeout bounds remain unchanged.
- Existing automatic retry limits remain unchanged.
- Corrupt/oversized settings continue to use the established safe fallback/recovery path.

## Security and protocol guarantees retained

Ghost FTP 1.6.0 retains the existing protocol boundaries:

- Explicit FTPS remains the default for new profiles.
- Plain FTP requires an explicit warning.
- TLS 1.2/1.3 uses standard .NET certificate-chain and hostname validation.
- No certificate-validation bypass is provided.
- Passive data sockets use the authenticated control host rather than trusting PASV redirect host data.
- FTP command arguments reject CR/LF/NUL injection.
- Replies, listing payloads and recursive traversal remain bounded.
- Remote root deletion remains blocked.
- Downloads retain `.ghostftp.part` resume and `SIZE` validation where available.
- Uploads retain temporary remote upload, verification, commit and rollback behavior.
- Saved passwords remain opt-in and DPAPI-protected for the current Windows user.

## Privacy and dependency guarantees retained

1.6.0 adds no analytics, telemetry SDK, advertising SDK, tracking SDK, crash-upload service, cloud profile synchronization, automatic background update checker or product background web request.

The optional keepalive is server-session maintenance traffic to the already selected FTP/FTPS server. It is configurable and can be disabled.

Shipping source remains C#-only and contains zero NuGet `PackageReference` entries.

## Languages

Ghost FTP continues to ship 29 selectable languages with English as the primary/default language and guaranteed fallback:

English, Croatian, German, French, Spanish, Italian, Portuguese, Dutch, Polish, Czech, Slovak, Slovenian, Hungarian, Romanian, Bulgarian, Greek, Turkish, Ukrainian, Russian, Serbian, Bosnian, Swedish, Danish, Norwegian, Finnish, Japanese, Korean, Simplified Chinese and Traditional Chinese.

No online translation service or language-pack download is used.

## Platform scope

The supported production GUI target remains Windows x64/ARM64 using WPF. `GhostFTP.Core` remains platform-neutral `net10.0` for future desktop renderers.

Android and iOS remain outside the shipping desktop scope and are rejected by the source audit. A production Linux GUI is not falsely claimed while the current GUI is WPF and the repository forbids third-party package dependencies.

See `docs/PLATFORM-SUPPORT.md`.

## Validation additions

Core self-tests now validate the richer transfer progress model, including byte summary, ETA behavior, completion state and normalization of unknown/non-positive totals.

The existing queue concurrency test, Core security tests, WPF input/localization/Setup smoke tests and source audit remain release gates.
