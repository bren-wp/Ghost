# Ghost FTP 0.1.3 Beta

Release channel: **Beta**  
Public version: **0.1.3**  
Informational version: **0.1.3-beta**  
Platforms: **Windows x64/ARM64 and Linux x64/ARM64**

Ghost FTP 0.1.3 Beta is a focused workstation-quality release built on the completed 0.1.2 line. It improves transfer management, Windows/Linux UI parity, installer presentation, queue observability and regression coverage without weakening the project's privacy, transport-security or dependency-minimal guarantees.

## Summary

- Adds honest queue-level pause/resume semantics without pretending an active FTP data stream can be safely frozen when resumable-transfer semantics were not negotiated.
- Adds broader retry and selective queue-history controls.
- Improves the Windows transfer workflow and brings the native Linux transfer panel to the same management model.
- Aligns Windows application and Setup styling with the shared canonical Ghost FTP palette.
- Polishes the Windows Setup wizard with clearer step progress, transactional-maintenance messaging and privacy-first installation copy.
- Keeps English as the authoritative primary/fallback language and preserves the existing 29-language local catalog.
- Keeps the shipping source Windows/Linux-only, with no Android, iOS or MacCatalyst target.

## New

### Transfer queue control

- `PauseQueue()` blocks dispatch of new queued and retrying jobs.
- `ResumeQueue()` releases paused workers safely.
- `IsQueuePaused` exposes queue state to both desktop renderers.
- `QueueStateChanged` allows UI state to update without polling.
- Running transfers intentionally continue when the queue is paused. This avoids presenting a fake mid-stream pause guarantee for FTP servers that may not support safe resume semantics.

### Queue history management

- Clear completed transfers only.
- Clear failed transfers only.
- Clear cancelled transfers only.
- Retain the existing clear-finished operation for users who want a single cleanup action.
- Retry all failed transfers from the Windows and Linux workstation flows.

### Windows transfer UX

The transfer queue context menu now provides:

- transfer details;
- pause/resume queue;
- retry selected;
- retry all failed;
- cancel selected;
- cancel all;
- clear completed;
- clear failed;
- clear cancelled;
- clear finished;
- copy source path;
- copy destination path.

The queue summary now reports running, retrying, queued, failed, cancelled and completed counts plus aggregate running throughput.

### Linux transfer UX

- Transfer rows are now selectable in the native X11/XWayland renderer.
- Selected rows receive the same accent-state treatment used elsewhere in the workstation.
- The transfer header exposes queue pause/resume, retry failed, selected/all cancellation and cleanup controls at appropriate window widths.
- Failed and completed states receive clearer status coloring.
- Queue-paused state is surfaced in the transfer summary.

## Improved

### UI / UX cleanup

- The dark Windows palette now consumes the same `GhostReferencePalette` tokens used by the canonical reference renderer.
- Cards, surfaces, buttons, badges, list rows and table headers use a tighter, more consistent workstation density.
- Keyboard-focus visibility on buttons is improved with the shared accent border.
- Hover, pressed and disabled button states are more consistent.
- The visual hierarchy is less rounded and less card-heavy, matching the compact professional FTP workstation direction established in 0.1.2.

### Windows Setup

- Setup now uses the shared canonical dark palette automatically.
- The default window is slightly wider to reduce cramped localized copy.
- The wizard header displays clear step progress.
- The left brand panel communicates local-only Setup behavior.
- Install options explain that one maintained `GhostFTP-Setup.exe` handles install/update/uninstall instead of generating a separate uninstaller executable.
- The Ready page explains staged validation and transactional rollback behavior.
- The Progress page surfaces package validation and maintenance semantics more clearly.
- The Finish page reiterates the no-account/no-telemetry local-first model.

### Localization

- Existing 29 selectable languages remain available locally.
- English (`en`) remains the primary language and final fallback.
- New transfer-management copy is isolated in a shared dependency-free text layer so untranslated technical controls always fall back to English rather than becoming blank or requiring an online translation service.
- Croatian has explicit transfer-management wording for the newly introduced queue operations.

## Fixed

- Linux transfer rows are now actually selectable, making selected-transfer cancellation deterministic instead of implicitly falling back to the last queue item.
- Queue-paused cancellation is handled without deadlocking a waiting worker.
- Queue disposal now releases paused dispatch waiters before shutting workers down.
- Selective queue cleanup no longer requires clearing unrelated history categories.
- Windows queue controls now keep the pause/resume label synchronized with the actual queue state.

## Security

0.1.3 preserves the 0.1.2 security invariants:

- fail-closed FTP security-mode validation;
- normal TLS certificate and hostname validation;
- strict Explicit FTPS `AUTH TLS` handling;
- `PBSZ 0` and `PROT P` for encrypted data channels;
- binary `TYPE I` for transfer data paths;
- passive-data host protection tied to the authenticated control host;
- CR/LF/NUL command-injection guards;
- bounded reply, traversal and queue limits;
- local path-safety checks;
- opt-in local password protection using Windows DPAPI or Linux AES-256-GCM user-private key material;
- no password logging or credential telemetry.

The queue pause feature does not weaken transport state by attempting to suspend a live data socket. It only gates future dispatch.

## Privacy

Ghost FTP 0.1.3 continues to include no application telemetry, analytics, advertising SDK, fingerprinting, hidden crash upload, cloud profile synchronization or automatic background update checker. Network access remains tied to user-directed FTP/FTPS operations, explicit user-opened links and release/test infrastructure outside the shipping application.

## Stability and performance

- Queue workers remain bounded to the configured concurrency limit.
- Paused workers wait asynchronously rather than spin-polling.
- Cancellation remains per-transfer and isolated from unrelated work.
- The queue keeps the existing bounded maximum of 4,096 queued jobs.
- New pause/resume and selective-cleanup behavior is covered by deterministic self-tests.
- Windows and Linux continue to share the same protocol, transfer and settings core.

## Testing

The 0.1.3 gate extends the existing test suite with explicit regression coverage for:

- paused queues not creating transfer sessions before resume;
- resume completing previously queued work;
- queue-state notifications;
- cancellation while dispatch is paused;
- selective completed-history cleanup;
- selective cancelled-history cleanup;
- selective failed-history cleanup;
- synthetic permanent transfer failure handling.

Existing Core, Demo workflow, transfer concurrency, Windows WPF input/localization, Linux X11/XWayland smoke, source audit, security audit, packaging and checksum gates remain mandatory.

## Setup and packaging

Windows release naming remains predictable:

- `setup.exe`
- `portable.exe`
- architecture-specific x64/ARM64 variants

Linux remains available as self-contained x64/ARM64 binaries and archives. No Android/iOS application packages are produced.

## Internal engineering

- Added `GhostTransferText` as the shared offline transfer-management copy layer.
- Extended `TransferQueueService` with asynchronous dispatch gating and selective history cleanup.
- Extended `GhostFTP.QueueSelfTest` for queue state and cleanup regressions.
- Updated the Linux X11/XWayland transfer renderer rather than introducing a second UI framework or third-party toolkit.
- Kept shipping projects free of third-party NuGet `PackageReference` dependencies.

## Known limitations

- Queue pause is deliberately a **dispatch pause**, not byte-stream suspension of transfers already running.
- Ghost FTP remains an FTP/FTPS client and does not claim SFTP/SSH support.
- Linux uses the system X11/XWayland ABI and therefore still requires the supported system X11 runtime libraries.
- The 0.x line remains Beta; the first stable release target is 1.0.0.

## Upgrade notes

0.1.3 can update an existing per-user Windows installation through the same Setup executable. Existing local profiles and settings remain local. Portable mode continues to keep its data beside the portable executable when the portable marker is active.
