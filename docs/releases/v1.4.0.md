# Ghost FTP 1.4.0

Release date: 2026-09-05

Ghost FTP 1.4.0 is a major reliability, localization, installer and FTP-integrity release. The product remains **Ghost FTP / GhostFTP**; the developer, publisher and licensor is **BRENDIGO LTD**.

## 29-language localization

English remains the primary/default language and final fallback. Ghost FTP 1.4.0 validates 29 selectable languages across the core application and guided Setup vocabulary:

English, Croatian, German, French, Spanish, Italian, Portuguese, Dutch, Polish, Czech, Slovak, Slovenian, Hungarian, Romanian, Bulgarian, Greek, Turkish, Ukrainian, Russian, Serbian, Bosnian, Swedish, Danish, Norwegian, Finnish, Japanese, Korean, Simplified Chinese and Traditional Chinese.

Localization is compiled into C# source and operates completely offline. No translation service, language-pack download or locale analytics is used.

## Guided Windows Setup

The installer is now a multi-step Windows 11-style wizard:

```text
Language → License → Install options → Ready → Install/Update → Finish
```

Key behavior:

- the Setup language also becomes the initial Ghost FTP client language;
- the repository `LICENSE` is embedded in Setup;
- the user must explicitly accept the license before installation can continue;
- install location and desktop-shortcut choice are reviewed before execution;
- the Ready page shows product, publisher, language and selected options;
- install/update failures return to Ready with a visible inline error message;
- successful installation offers Launch Ghost FTP.

## Uninstall architecture

Ghost FTP no longer generates a separate uninstaller executable.

Windows Installed Apps points to the installed maintenance copy:

```text
GhostFTP-Setup.exe --uninstall
```

Uninstall removes the client, shortcuts and Installed Apps registration and can optionally remove local profiles/settings. When the running Setup process must remove itself, Ghost FTP registers Windows delete-on-reboot as a fallback and also starts a delayed local cleanup attempt after process exit.

## Connection and transfer reliability

- Added configurable automatic transfer retries from 0 to 5.
- Retries are limited to transient socket/timeout failures and FTP 4xx replies.
- Authentication, certificate, permission and permanent 5xx failures are not blindly retried.
- Added visible Retrying state and retry count in the queue.
- Fixed cancellation during retry backoff so cancelling one transfer cannot terminate the queue worker.
- Added configurable connect, command and transfer-idle timeouts.
- Preserved independent FTP/FTPS sessions for queued transfers.

## Server working-directory consistency

Remote navigation now synchronizes through server `CWD` and `PWD`.

The visible Remote path is therefore the path confirmed by the server rather than a client-side assumption, reducing divergence on servers with non-trivial working-directory semantics.

## Download integrity

When server `SIZE` is available, Ghost FTP verifies the completed `.ghostftp.part` file length against the expected remote length before promoting the partial file into the requested local destination.

A mismatch remains a failed transfer and the partial file is retained for safe resume instead of being mislabeled as complete.

## Upload integrity and rollback

Uploads continue to use a unique temporary remote file. When `SIZE` is available, 1.4.0 verifies the temporary upload length before commit and the final destination length after commit.

When replacing an existing remote file:

1. the old destination is moved to a rollback backup;
2. the verified temporary upload is renamed into place;
3. the committed destination is checked again;
4. the backup is removed only after successful final verification.

If final verification fails, Ghost FTP attempts to remove the invalid destination and restore the previous backup.

This is a byte-length integrity boundary using FTP `SIZE`, not a cryptographic checksum claim.

## Connection Diagnostics

Added user-initiated Connection Diagnostics against the active server. Diagnostics can inspect:

- `NOOP` control-channel health;
- `SYST` server identity text;
- `PWD` current directory;
- known `FEAT` capabilities;
- current TLS/plain transport state.

Results remain local and are never uploaded to Ghost FTP or BRENDIGO LTD.

## Setup/persistence hardening

- Setup validates both the embedded client payload and the installed maintenance Setup copy as Windows executables.
- Existing client replacement retains temporary-file and atomic-replacement semantics where supported.
- A locked/running client causes an explicit failure rather than false success.
- Existing valid settings are preserved when Setup stores the selected language.
- Malformed or oversized settings are quarantined/neutralized rather than trusted.
- Password persistence remains opt-in and protected with Windows DPAPI.

## Security and privacy

1.4.0 preserves and expands the existing boundaries:

- FTPS certificate/hostname validation;
- no certificate-bypass switch;
- offline revocation cache to avoid hidden CRL/OCSP network calls;
- CR/LF/NUL FTP command-argument rejection;
- bounded control replies and LIST/MLSD payloads;
- passive-host hardening;
- path canonicalization and root-delete blocking;
- traversal depth/item budgets;
- NTFS reparse-point protection;
- verified ambiguous `MKD 550` behavior;
- bounded local settings/profile input;
- no application telemetry, analytics, ads, tracking SDK, crash upload or background update checker.
