# Ghost FTP 0.1.2 Beta

Ghost FTP 0.1.2 Beta is a workstation-quality refinement release focused on a cleaner file-transfer workflow, safer connection lifecycle handling, Windows/Linux desktop parity, and stricter release auditing. It keeps the 0.x public line in Beta while preserving the complete 0.1.0 and 0.1.1 release history.

## Highlights

- Reworked the Windows workstation shell around the approved dark Ghost FTP visual language without replacing the functional FTP client with a mock UI.
- Removed duplicated global **New folder**, **Rename**, and **Delete** actions. File operations now live in the Local and Remote pane toolbars where their target is unambiguous.
- Added real drag resizing for the server sidebar, Connection Log / Quick Connect area, Local / Remote panes, and Transfers queue. Double-click resets each splitter to a sensible default.
- Reduced the minimum Windows workstation size while keeping the canonical 1914 × 907 documentation capture and full maximize/minimize/restore behavior.
- Rebuilt Quick Connect spacing so Host, Port, Security, Username and Password remain readable and aligned. Connection actions and the session-only privacy option are kept on a separate compact row.
- Compact windows automatically give the main toolbar the full width instead of allowing the optional language/search overlay to collide with primary controls.
- Hardened Windows connection input validation before DNS resolution or FTP command construction, while retaining protocol-boundary validation in `FtpSession`.
- Hardened disconnect teardown by clearing authoritative session/credential-routing state before QUIT/disposal, preventing transfer workers or keepalive callbacks from observing a stale active session.

## Security and privacy

Ghost FTP 0.1.2 preserves the existing fail-closed transport rules:

- Explicit FTPS requires a successful 2xx `AUTH TLS` response and normal TLS certificate/hostname validation.
- Encrypted sessions require `PBSZ 0` and `PROT P`; Ghost FTP does not silently downgrade an FTPS request to plaintext FTP.
- Binary data transfer is negotiated with `TYPE I` before send/receive paths.
- Passive data connections remain tied to the authenticated control host instead of trusting an arbitrary server-advertised address.
- Host, port, username, password, remote path and remote name input is bounded and control characters are rejected before command construction.
- Plain FTP remains available only as an explicit user choice and displays a warning because credentials and data are not TLS protected.
- Session-only Quick Connect profiles never persist passwords.
- Windows saved passwords are opt-in and protected for the current Windows user with DPAPI.
- Linux saved passwords are opt-in and protected with AES-256-GCM using local per-user key material.
- There is no application telemetry, analytics, advertising SDK, tracking SDK, automatic crash upload, cloud profile sync or hidden background update check.

## Windows workstation UX

The Windows renderer remains native WPF and self-contained. The 0.1.2 shell is deliberately closer to a professional dual-pane transfer workstation:

1. A resizable saved-server sidebar stays on the left.
2. Menu and primary connection/transfer actions stay at the top.
3. Connection Log and Quick Connect share the top work area.
4. Local and Remote file panes remain the central working area and can be resized horizontally.
5. The Transfers queue remains below the file panes and can be resized vertically.
6. Context-specific create/rename/delete actions are available only in the Local and Remote pane toolbars, eliminating target ambiguity.

The main window keeps native resize, minimize, maximize and restore behavior. Existing Local/Remote pane ratio, transfer-panel height and maximized state persistence remain intact.

## Linux parity

Linux remains a real native X11/XWayland desktop renderer rather than a wrapper around the Windows executable or a browser UI. It continues to share:

- `GhostFTP.Core` FTP/FTPS protocol and transfer logic;
- `GhostFTP.Design` product identity, palette and localization catalog;
- the same saved-site model and session-only Quick Connect semantics;
- the same transfer queue, cancellation/retry model and keepalive behavior;
- the same privacy and security guarantees.

The release CI builds and exercises both Windows and Linux before publication. Platform-native rendering details can differ where WPF and X11 have different window-system primitives, but feature semantics and the approved Ghost FTP workstation hierarchy remain aligned.

## Localization

English (`en`) remains the primary language and authoritative fallback. Ghost FTP ships a completely local catalog of **29 selectable languages**:

English, Croatian, German, French, Spanish, Italian, Portuguese, Dutch, Polish, Czech, Slovak, Slovenian, Hungarian, Romanian, Bulgarian, Greek, Turkish, Ukrainian, Russian, Serbian, Bosnian, Swedish, Danish, Norwegian, Finnish, Japanese, Korean, Chinese (Simplified), and Chinese (Traditional).

No online translation service is contacted. Windows, Linux and Windows Setup consume the same local catalog.

## Setup and packaging

Windows continues to publish:

- `setup.exe` — canonical x64 Setup and maintenance executable;
- `portable.exe` — canonical x64 portable executable;
- `setup-arm64.exe` and `portable-arm64.exe`;
- descriptive architecture-specific aliases;
- `SHA256SUMS.txt` and signing information.

Setup remains per-user and self-contained. The installed maintenance `GhostFTP-Setup.exe` handles update and uninstall; no separate `uninstall.exe` is introduced. Candidate application and maintenance binaries are validated before commit, downgrade protection remains active, and rollback attempts to restore both previous binaries if a later installation stage fails.

Linux continues to publish self-contained x64 and ARM64 executables plus `.tar.gz` archives. The native renderer uses the system `libX11.so.6` ABI; no third-party GUI package is added to the repository.

## Dependency and platform scope

Shipping projects contain **zero third-party NuGet `PackageReference` entries**. Ghost FTP relies on the .NET runtime/framework APIs and audited OS facilities required by the native Windows and Linux renderers.

This repository intentionally ships **Windows and Linux desktop applications only**. Android, iOS, MacCatalyst and other mobile application source/targets are not part of the 0.1.2 line, and the source audit fails if mobile targets are reintroduced.
