# Ghost FTP 0.1.0 Beta

Ghost FTP 0.1.0 Beta is the first public release in the clean pre-1.0 line. It ships one privacy-first FTP/FTPS product across native Windows and Linux desktop renderers while keeping protocol, persistence, transfer and security behavior in shared .NET 10 code.

## Release identity

- Product: **Ghost FTP**
- Version: **0.1.0**
- Channel: **Beta**
- Informational version: **0.1.0-beta**
- Publisher/developer: **BRENDIGO LTD**
- Windows: **x64 / ARM64**
- Linux: **x64 / ARM64**
- First stable target: **1.0.0**

## Desktop architecture

```text
src/GhostFTP.Core      shared FTP/FTPS, path safety, persistence and transfer queue
src/GhostFTP.Design    shared product identity, localization and visual contract
src/GhostFTP.App       Windows WPF renderer
src/GhostFTP.Setup     Windows installer / maintenance app
src/GhostFTP.Linux     Linux X11/XWayland renderer
```

Windows and Linux use the same FTP/FTPS engine. They also share the Ghost FTP reference palette, product identity, localization catalog and workstation information hierarchy. Native WPF and X11 font/window rasterization can differ by operating system, but that difference is not used as an excuse for protocol, privacy or core-workflow drift.

## FTP / FTPS security hardening

Final 0.1.0 hardening includes:

- invalid/undefined `FtpSecurityMode` values are rejected when creating a real session instead of being allowed to fall through to plain FTP;
- Explicit FTPS accepts only a positive **2xx** `AUTH TLS` reply before TLS upgrade;
- both Windows and Linux require explicit confirmation before real plain FTP;
- TLS 1.2 and TLS 1.3 use normal certificate-chain and hostname validation;
- there is no certificate-validation bypass mode;
- FTPS requires `PBSZ 0` and `PROT P` so the data channel remains protected;
- every data transfer requires successful binary mode (`TYPE I`) rather than continuing after a refused mode command;
- EPSV is preferred with PASV fallback;
- PASV data connections use the authenticated control host rather than trusting an arbitrary PASV host redirect;
- FTP command arguments reject CR/LF/NUL injection content;
- server replies, listing payloads, recursive depth and aggregate item counts are bounded;
- remote-root deletion remains blocked.

## Linux reliability parity

The Linux renderer received an additional connection-lifecycle pass:

- failed candidate sessions are disposed;
- active connection options are set only after authentication succeeds;
- cancellation during initial navigation is no longer swallowed as a path fallback;
- active options are cleared on failure/disconnect;
- late directory-listing results from a replaced session are discarded;
- server-only keepalive now follows the same stale-session behavior as Windows;
- failed keepalive marks the current session lost and does not silently reconnect;
- Demo mode remains local-only and skips keepalive.

## Transfer reliability

The queue retains:

- 1–8 concurrent real transfers, default 3;
- queue capacity 4,096;
- isolated FTP/FTPS transfer sessions;
- per-job cancellation and Cancel all;
- transient-only retry policy;
- transferred bytes, speed, ETA, retries and timestamps;
- resume using `.ghostftp.part` where supported;
- server `SIZE` verification when available;
- remote temporary upload names and rollback backup for destination replacement.

Authentication, permission, permanent FTP 5xx and TLS/certificate failures are not blindly retried.

## Local credential protection

### Windows

Optional saved passwords use CurrentUser DPAPI.

### Linux

Optional saved passwords use AES-256-GCM with a cryptographically random local 256-bit key. The key file is restricted to the current user (`0600`) where Unix permissions are available. The design is documented as local file-based protection rather than being falsely described as a hardware-backed credential vault.

Session-only Quick Connect (**Keep in this tab**) remains memory-only and is filtered out of `profiles.json` persistence.

## Windows Setup hardening

Setup now validates more than a minimal `MZ` header before committing an executable. It verifies:

- minimum payload size;
- Windows executable signature;
- ProductName = Ghost FTP;
- CompanyName = BRENDIGO LTD;
- exact file version matching Setup.

When updating an existing app, the previous executable remains available as a rollback copy until later install stages complete. A failure after application replacement therefore triggers rollback rather than intentionally leaving a half-updated app.

`QuietUninstallString` is not advertised because the current uninstaller is interactive. The normal Installed Apps uninstall command remains available.

## Privacy

Ghost FTP 0.1.0 Beta contains no application telemetry, analytics SDK, advertising SDK, tracking SDK, automatic crash uploader, cloud profile sync or automatic background product-update checker.

Normal runtime network behavior is limited to the FTP/FTPS server explicitly selected by the user, server-only diagnostics/keepalive on that connection and website links explicitly opened by the user.

Keepalive uses standard FTP `NOOP`, can be disabled with `0`, skips Demo mode and never calls a Ghost FTP/BRENDIGO LTD analytics endpoint.

## Real-server smoke harness

0.1.0 now includes `tests/GhostFTP.LiveSmoke` and `.github/workflows/live-smoke.yml` for non-destructive real-server validation.

Credentials are not committed. They must be supplied through local environment variables or GitHub Actions repository secrets. The harness performs:

```text
connect → PWD → LIST → NOOP → disconnect
```

It does not upload, download, rename, delete or create remote data. Plain FTP live testing is disabled unless explicitly opted in. See `docs/LIVE-SMOKE-TEST.md`.
