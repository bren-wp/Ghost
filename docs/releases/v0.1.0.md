# Ghost FTP 0.1.0 Beta

Ghost FTP 0.1.0 Beta is the first release in the clean public pre-1.0 version line. It carries forward the completed protocol, desktop, installer, localization, privacy, security and transfer work developed during the preserved internal history while resetting the public version sequence to a conventional Beta line.

## Release status

- Public version: **0.1.0**.
- Release channel: **Beta**.
- Informational version: **0.1.0-beta**.
- First planned stable release: **1.0.0**.
- Publisher/developer: **BRENDIGO LTD**.
- Desktop implementations: **Windows and Linux**.
- Windows architectures: **x64 and ARM64**.
- Linux architectures: **x64 and ARM64**.
- Shared FTP/FTPS engine: platform-neutral **.NET 10**.

A failed required quality gate means 0.1.0 Beta is not release-ready.

## Shared architecture

Both desktop clients use the same `GhostFTP.Core` implementation for FTP/FTPS, listing/parsing, path validation, transfer sessions, queue state and reliability policy.

```text
src/GhostFTP.Core      shared protocol / transfer / safety engine
src/GhostFTP.Design    shared identity and localization + Windows visual helpers
src/GhostFTP.App       Windows WPF desktop renderer
src/GhostFTP.Setup     Windows installer / maintenance application
src/GhostFTP.Linux     Linux X11/XWayland desktop renderer
```

Linux is therefore not a renamed Windows executable and does not fork the FTP implementation.

## Professional FTP workstation

0.1.0 Beta uses a dense workstation layout modeled around familiar desktop FTP ergonomics:

- permanent **File / View / Sites / Transfers / Tools / Help** hierarchy;
- compact global action toolbar;
- Saved Sites / Site Manager workflow;
- Connection Log and Quick Connect area;
- large Local / Remote file panes;
- full-width Transfers queue;
- connection/privacy status area;
- locally persisted workspace preferences;
- dark/light/system appearance.

The UI gives file browsing and transfer state priority over decorative chrome.

## Site Manager and saved profiles

The saved-profile model supports:

- site name;
- host / IP / URL;
- port;
- FTP, explicit FTPS and implicit FTPS;
- username;
- password;
- optional saved-password protection where exposed by the platform UI;
- default remote path;
- immediate Connect;
- local Save / Remove;
- protected built-in Demo profile.

Windows saved passwords use CurrentUser DPAPI. Linux provides AES-256-GCM local credential protection backed by a cryptographically random per-user key file. On Linux the key file is hardened to `0600` where Unix filesystem permissions are available. The Linux design is intentionally documented as local file-based protection rather than being misrepresented as equivalent to Windows DPAPI or a hardware-backed secret store.

## Windows Authenticode signing

0.1.0 Beta introduces a private-key-safe release signing path.

The release workflow can:

- receive a PFX only from GitHub Actions secrets;
- import it temporarily without making the private key exportable;
- require the Code Signing EKU;
- sign release executables with SHA-256 Authenticode;
- optionally timestamp signatures;
- verify the signer after signing;
- regenerate `SHA256SUMS.txt` from the final signed bytes;
- publish a `SIGNING.txt` report;
- remove the imported certificate and temporary PFX material.

The repository also contains a local RSA-3072/SHA-256 self-signed development certificate helper for testing signing mechanics. A self-signed certificate is **not** presented as a SmartScreen/Unknown Publisher solution. A normal trusted publisher identity requires an appropriate CA-issued code-signing certificate for **BRENDIGO LTD**.

Stable releases require trusted Authenticode validation in the release pipeline.

## Linux desktop implementation

0.1.0 Beta includes a real Linux desktop renderer in `src/GhostFTP.Linux`.

The Linux client:

- uses the same `GhostFTP.Core` protocol implementation;
- uses the same shared product identity and localization catalog;
- implements the same major professional workspace hierarchy;
- uses direct X11 client ABI integration instead of adding a third-party NuGet GUI framework;
- runs on X11 and can run on Wayland desktops through XWayland;
- stores settings and profiles locally;
- contains no telemetry or tracking SDK;
- supports local/remote navigation, filtering, create/rename/delete, uploads/downloads, transfer queue, settings and diagnostics;
- supports x64 and ARM64 release targets.

The Linux desktop runtime requires the standard `libX11.so.6` client library. This is an operating-system desktop library, not a Ghost FTP cloud dependency or downloaded analytics/runtime service.

## FTP / FTPS protocol behavior

The shared engine supports:

- FTP;
- Explicit FTPS (`AUTH TLS`);
- Implicit FTPS;
- TLS 1.2 and TLS 1.3;
- normal .NET certificate-chain and hostname validation;
- no certificate-validation bypass switch;
- EPSV with PASV fallback;
- passive data connections hardened to the authenticated control host;
- UTF-8 negotiation where supported;
- MLSD with LIST fallback;
- server-confirmed `CWD` / `PWD` navigation;
- `REST`-based download resume where supported;
- `SIZE`-assisted verification where available;
- temporary remote upload paths before commit;
- rollback backup when safely replacing a remote file;
- create folder, rename, delete, upload, download and recursive folder operations;
- remote-root deletion protection;
- bounded reply, listing and traversal processing;
- connection diagnostics and configurable server-only keepalive.

## Transfer queue and reliability

The transfer workstation retains:

- bounded queue capacity;
- configurable concurrent transfers from 1 to 8;
- default concurrent-transfer count of 3;
- isolated real FTP/FTPS transfer sessions;
- per-job cancellation;
- Cancel all;
- transient-only automatic retries from 0 to 5;
- queued/running/retrying/completed/failed/cancelled states;
- transferred bytes and known total;
- current speed;
- ETA when calculable;
- retry count;
- start/finish timestamps;
- local error detail.

Authentication failures, certificate failures, permission errors and permanent FTP 5xx responses are not blindly retried.

## Connection resilience

Configurable control-channel keepalive remains server-only:

- standard `NOOP` against the already selected FTP server;
- disabled with `0`;
- enabled values bounded to 15–600 seconds;
- default 60 seconds;
- no hidden request to Ghost FTP, BRENDIGO LTD, GitHub or an analytics endpoint;
- stale control state is invalidated after confirmed keepalive/diagnostic failure;
- reconnect remains an explicit user action.

Connection Diagnostics can inspect active server health, `SYST`, `PWD`, known `FEAT` capabilities and TLS/plain state.

## Cross-platform local path safety

0.1.0 Beta removes Windows-only filename assumptions from the shared download safety layer.

- Windows reserved device names and Windows-invalid characters are escaped on Windows.
- Linux-valid names such as `CON.txt` or filenames containing `:` are not unnecessarily rewritten on Linux.
- resolved local destinations are checked with relative-path containment logic so they remain under the selected local root.
- traversal-style remote listing names remain rejected/ignored by the shared parser/input guards.

## File-workspace behavior

Desktop renderers retain equivalent major workflows:

- directly editable local and remote paths;
- local home/shortcut navigation appropriate to the platform;
- remote root and parent navigation;
- filtering/search;
- create folder, rename, refresh and delete operations;
- upload/download actions;
- transfer queue state and cancellation;
- saved sites;
- local settings;
- local Connection Log.

Windows additionally retains extended WPF multi-selection, drag-and-drop upload, File Explorer integration, remote permissions display and the full focus-routed shortcut set. Linux parity is defined as equivalent core capability/safety and information hierarchy, not pretending that WPF and X11 are identical native widget systems.

## Setup and uninstall

### Windows

`setup.exe` remains the guided Windows Setup application:

```text
Language → License → Install options → Ready → Install/Update → Finish
```

It embeds the repository license, requires explicit acceptance, validates its payload, installs per-user by default, supports optional desktop shortcut creation, registers Installed Apps, updates through the same maintenance path and uses installed `GhostFTP-Setup.exe --uninstall` rather than generating a separate uninstaller executable.

### Linux

Architecture-specific Linux tarballs include user-local installation and uninstall scripts. They do not require Ghost FTP telemetry, an account, a package-manager repository or a background service.

## Localization

The existing 29-language catalog remains part of the 0.1.0 Beta source line. English is the primary/default language and guaranteed fallback. Language data is compiled locally; Ghost FTP does not use an online translation service or download language packs at runtime.

## Privacy

0.1.0 Beta retains the local-first privacy model:

- no application telemetry;
- no analytics SDK;
- no advertising SDK;
- no tracking SDK;
- no automatic crash-report upload service;
- no cloud profile synchronization;
- no automatic background product update checker;
- no background request to ghostftp.com or brendigo.com;
- transfer metrics remain local UI state.

Normal application network traffic is limited to the FTP/FTPS server selected by the user, documented keepalive/diagnostics on that selected connection and website links explicitly opened by the user.

Code signing is a build/release operation and does not add a runtime signing-service dependency.

## Authentic repository screenshots

The Windows repository screenshot pipeline remains tied to the real compiled WPF client.

The client supports:

```powershell
--capture-ui <directory>
```

CI opens the local Demo session and captures the real MainWindow and Site Manager. These screenshots are not AI mockups and require no external image-generation request.

## Dependency policy

- Shipping source remains C#-centric.
- Shipping projects contain zero third-party NuGet `PackageReference` entries.
- Windows uses operating-system/.NET WPF facilities.
- Linux uses direct `libX11.so.6` desktop integration.
- `GhostFTP.Core` remains platform-neutral `net10.0`.
- Android and iOS remain outside the current shipping scope.

4. dependency/privacy/product/publisher/platform/signing source audit;

10. Linux x64/ARM64 self-contained packaging;

## Stable 1.0.0 gate

Ghost FTP must not be presented as stable before the corresponding platform implementations reach the production-complete quality gate. The first stable public version is **1.0.0**.

For Windows, stable release publication additionally requires trusted Authenticode validation. Linux stable artifacts must pass their own build/test/package/checksum gates.
