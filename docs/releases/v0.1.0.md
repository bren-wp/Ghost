# Ghost FTP 0.1.0 Beta

Ghost FTP 0.1.0 Beta is the first release in the clean public pre-1.0 version line.

The version number has been reset from the earlier internal development numbering, but the product itself has **not** been reset. No completed FTP/FTPS engine, desktop UI, Setup, localization, privacy, security, transfer, testing or documentation work has been intentionally removed. The earlier 1.x release-note files remain in the repository as historical engineering snapshots.

## Release status

- Public version: **0.1.0**.
- Release channel: **Beta**.
- Informational version: **0.1.0-beta**.
- First planned stable release: **1.0.0**.
- Canonical Windows package names remain `portable.exe` and `setup.exe` plus their ARM64 and architecture-explicit variants.
- Until Ghost FTP reaches the stable gate, canonical packages are Beta builds of the current 0.x version.

## Professional FTP workstation

0.1.0 Beta includes the professional workstation layout already developed before the numbering reset:

- permanent **File / View / Sites / Transfers / Tools / Help** menu groups;
- compact global action toolbar;
- Saved Sites navigation;
- Connection Log and Quick Connect area;
- large Local / Remote dual-pane file tables;
- full-width Transfers queue;
- resizable Saved Sites/main workspace split;
- resizable Local/Remote split;
- resizable browser/Transfers split;
- splitter double-click reset behavior;
- locally persisted and normalized workspace geometry;
- dark/light/system appearance using the Ghost FTP design system.

The goal of the layout is high information density and predictable navigation without abandoning the Ghost FTP visual identity.

## Site Manager

The Beta includes the first-class Site Manager already implemented in the current source tree.

It supports the real saved-profile model:

- site name;
- host / IP / URL;
- port;
- FTP, explicit FTPS and implicit FTPS security modes;
- username;
- password;
- optional Remember password;
- default remote path;
- immediate Connect;
- local Save;
- protected built-in Demo profile.

Saved passwords remain opt-in and use Windows DPAPI in current-user scope. Global timeout, retry, keepalive and concurrency policy remains centralized in Settings rather than being duplicated as misleading per-site fields.

## FTP / FTPS protocol behavior

The existing protocol implementation is retained in 0.1.0 Beta:

- FTP;
- Explicit FTPS (`AUTH TLS`);
- Implicit FTPS;
- TLS 1.2 and TLS 1.3;
- normal .NET/Windows certificate-chain and hostname validation;
- no certificate-validation bypass switch;
- EPSV with PASV fallback;
- passive data connections hardened to the authenticated control host;
- UTF-8 negotiation where supported;
- MLSD with LIST fallback;
- server-confirmed `CWD` / `PWD` navigation;
- `REST`-based download resume where supported;
- `SIZE`-assisted download verification;
- temporary-file upload and commit flow;
- pre-commit and post-commit remote size verification where available;
- rollback backup when safely replacing a remote file;
- create folder, rename, delete, upload, download and recursive folder operations;
- root-delete protection;
- bounded reply, directory-listing and traversal processing.

## Transfer queue and reliability

The existing transfer workstation behavior is retained:

- bounded queue capacity;
- configurable concurrent transfers from 1 to 8;
- default concurrent-transfer count of 3;
- isolated real FTP/FTPS transfer sessions;
- per-job cancellation;
- Cancel all;
- transient-only automatic retries from 0 to 5;
- visible queued/running/retrying/completed/failed/cancelled states;
- transferred bytes and known total;
- current speed;
- ETA when calculable;
- retry count;
- start/finish timestamps;
- aggregate live throughput;
- per-transfer details;
- retry selected and clear-finished actions.

Authentication failures, certificate failures, permission errors and permanent FTP 5xx responses are not blindly retried.

## Connection resilience

The Beta keeps configurable FTP control-channel keepalive:

- standard `NOOP` only against the already-selected real server session;
- disabled with `0`;
- enabled values bounded to 15–600 seconds;
- default 60 seconds;
- skipped in Demo mode;
- no hidden request to Ghost FTP, BRENDIGO LTD, GitHub or an analytics endpoint;
- stale control state is invalidated after a confirmed keepalive or diagnostic failure;
- reconnect remains an explicit user action.

Connection Diagnostics remains user-initiated and can inspect control health, `SYST`, `PWD`, known `FEAT` capabilities and TLS/plain state for the active server.

## File-workspace behavior

The current Local / Remote workflow is preserved:

- directly editable local and remote paths;
- Local Home, Desktop, Documents and Downloads shortcuts;
- Remote root and parent navigation;
- filtering/search;
- responsive file columns;
- server-provided Remote Permissions where available;
- extended multi-selection;
- drag-and-drop upload from Windows;
- new folder, rename, refresh and delete operations;
- path copy actions;
- Open in File Explorer for Local items;
- optional hidden/system item display;
- focused item and selection summaries.

Keyboard routing remains context-aware so destructive actions target the pane that actually owns focus.

## Keyboard safety

The Beta retains focus-safe shortcuts:

- `F5` refreshes the active Local/Remote pane;
- `F2` renames in the active Local/Remote pane;
- `Delete` deletes only in the active file pane after normal confirmation policy;
- `Delete` while Transfers owns focus cancels the selected transfer;
- `Ctrl+F` focuses the active pane filter;
- `Ctrl+L` focuses the active path field;
- `Ctrl+A` selects all in Local, Remote or Transfers according to focus;
- `Enter` opens/activates the selected file item;
- `Backspace` navigates to the parent directory.

No non-file region silently falls back to Local for a destructive operation.

## Setup and uninstall

`setup.exe` remains the guided Windows Setup application using the same Ghost FTP design system.

Install/update flow:

```text
Language → License → Install options → Ready → Install/Update → Finish
```

Setup continues to:

- embed the repository license;
- require explicit license acceptance;
- support the same local language system;
- validate the embedded application payload;
- install per-user without requiring administrator rights for the normal path;
- create optional desktop shortcuts;
- register Ghost FTP in Windows Installed Apps;
- update existing installs through the same maintenance path;
- use installed `GhostFTP-Setup.exe --uninstall` for uninstall;
- avoid generating a separate uninstaller executable;
- optionally preserve or remove local settings/profiles during uninstall.

## Localization

The existing 29-language architecture remains part of the Beta source line. English is the primary/default language and fallback. Language catalogs are compiled into the product; Ghost FTP does not use an online translation service or download language packs at runtime.

## Privacy

0.1.0 Beta retains the local-first privacy model:

- no application telemetry;
- no analytics SDK;
- no advertising SDK;
- no tracking SDK;
- no crash-report upload service;
- no cloud profile synchronization;
- no automatic background product update checker;
- no background request to ghostftp.com or brendigo.com;
- transfer metrics remain local UI state.

Network traffic is limited to the FTP/FTPS server selected by the user, optional documented keepalive/diagnostics on that selected connection and website links explicitly opened by the user.

## Authentic repository screenshots

The repository screenshot system remains part of the Beta line.

The real compiled WPF client supports documentation capture through:

```powershell
--capture-ui <directory>
```

CI launches the production MainWindow in the built-in local Demo mode and captures the actual Ghost FTP client and Site Manager. Canonical repository screenshots are therefore generated from the real shipping UI, not from AI-generated mockups or an external design service.

## Dependency and platform policy

- Shipping source remains C#-only.
- Shipping source contains zero NuGet `PackageReference` entries.
- Windows x64 and ARM64 are the current production GUI targets.
- `GhostFTP.Core` remains platform-neutral `net10.0` for future real desktop renderers.
- Android and iOS remain outside the shipping scope.
- A Linux GUI is not claimed until an actual renderer exists and passes the documented parity/security/privacy gates.

## Versioning reset and preserved history

The repository previously used 1.x numbers during rapid internal development. Those records are intentionally preserved under the existing release-note filenames and in the cumulative changelog.

From this point forward, the public sequence starts at **0.1.0 Beta** and advances through the 0.x line until the product is considered complete and stable enough for **1.0.0**.

See `docs/VERSIONING.md` for the authoritative numbering contract.

## Validation requirements

The exact 0.1.0 Beta release commit must pass:

1. .NET 10 restore;
2. warning-as-error Release build;
3. dependency/version/channel/privacy/product/publisher/platform source audit;
4. Core security and correctness self-tests;
5. bounded parallel transfer queue/session/cancellation tests;
6. Windows/WPF editable-input and localization smoke tests;
7. live production MainWindow/Site Manager capture;
8. x64 and ARM64 self-contained packaging for an actual release run;
9. canonical `portable.exe` / `setup.exe` and ARM64 package verification;
10. SHA-256 manifest generation.

A failed required gate means 0.1.0 Beta is not release-ready.

## Stable 1.0.0 gate

Ghost FTP must not be presented as stable before the project reaches the agreed production-complete state. When that happens, the first stable version is **1.0.0**, and the canonical `portable.exe` and `setup.exe` packages must carry the matching stable 1.0.0 product/file metadata.
