# Ghost FTP 0.1.1 Beta

Ghost FTP 0.1.1 Beta is a focused reliability, installer-safety and regression-testing release on top of the first public 0.1.0 Beta line. It preserves the existing premium Windows/Linux workstation, FTP/FTPS protocol engine, privacy model and zero-third-party-`PackageReference` shipping policy while tightening failure handling and release verification.

## What changed from 0.1.0 Beta

### Complete local Demo regression workflow

The built-in local-only Demo mode is now exercised end to end on both Windows and Linux CI. The regression workflow validates:

```text
connect
→ diagnostics
→ PWD/CWD
→ LIST
→ NOOP keepalive
→ download
→ upload/download byte-for-byte round trip
→ rename
→ create/delete directory
→ recursive directory upload/download
→ cleanup
→ root-delete protection
→ disconnect
→ rejection of operations after disconnect
```

The test also verifies conflict safety: a file upload cannot replace an existing directory and a directory upload cannot replace an existing file. Blocked operations must leave the pre-existing Demo tree intact.

Demo mode remains fully local. It does not open an FTP socket, contact an analytics service or transmit test data outside the process.

### Demo session lifecycle hardening

`DemoFtpSession` now explicitly implements local diagnostics and keepalive behavior, resets its working directory on disconnect/disposal and consistently rejects post-disconnect operations. This keeps the local test profile aligned with the real-session lifecycle contract without pretending that Demo traffic is encrypted or remote.

### Transactional Windows application + Setup update

Windows Setup now treats the application executable and installed maintenance Setup copy as one staged binary transaction:

- both candidate binaries are staged before the active installation changes;
- both candidates are validated for minimum size, Windows executable identity, ProductName **Ghost FTP**, CompanyName **BRENDIGO LTD** and exact file version;
- existing application and Setup binaries retain rollback copies until every install stage succeeds;
- if a later install stage fails, Setup attempts to restore both previous binaries;
- first-time partial installations remove newly committed binaries during rollback;
- stale application and Setup transaction files are cleaned during uninstall;
- downgrade attempts are rejected by comparing installed and candidate file versions.

The interactive uninstaller remains explicit. `QuietUninstallString` is intentionally absent until Ghost FTP implements a genuine silent uninstall path.

### Security and privacy invariants preserved

0.1.1 retains the 0.1.0 transport hardening:

- invalid FTP security enum values fail closed;
- Explicit FTPS requires a positive 2xx `AUTH TLS` response before TLS upgrade;
- no automatic FTPS → FTP downgrade;
- plain FTP requires explicit user confirmation;
- TLS 1.2/1.3 use normal certificate-chain and hostname validation;
- no trust-all/certificate-bypass switch;
- FTPS data channels require `PBSZ 0` + `PROT P`;
- data operations require successful `TYPE I` binary mode;
- EPSV is preferred with PASV fallback;
- PASV connects to the authenticated control host rather than an arbitrary PASV-advertised host;
- FTP command arguments reject CR/LF/NUL injection content;
- reply/listing/traversal/queue resources remain bounded;
- remote-root deletion and local path containment safeguards remain active.

Ghost FTP still contains no application telemetry, analytics SDK, advertising SDK, tracking SDK, automatic crash uploader, cloud profile sync or automatic background product-update checker.

### Windows/Linux parity preserved

Both native renderers continue to share `GhostFTP.Core` and `GhostFTP.Design`. The approved workstation hierarchy remains:

```text
product / saved-sites / privacy rail
→ File / View / Sites / Transfers / Tools / Help
→ compact toolbar + Remote search
→ Connection Log + Quick Connect
→ Local + Remote panes
→ Transfers
→ connection/privacy status
```

WPF and X11/XWayland can differ in operating-system font rasterization/window chrome, but 0.1.1 does not introduce a separate FTP engine, alternate privacy policy or divergent workstation structure.

### Authentic repository UI

The README continues to use `assets/readme/ghostftp-client.png`, generated from the real compiled Windows application in local-only Demo mode. The dedicated screenshot workflow refreshes the production MainWindow/Site Manager captures after relevant `main` changes rather than substituting mock or generated UI images.

## Release-control cleanup

The hardening audit now derives the required release trigger and expected GitHub tag from the active `VERSION` / `RELEASE_CHANNEL` values instead of hardcoding 0.1.0. Obsolete pre-reset release-trigger marker files were removed; historical engineering release notes remain preserved for traceability.

## Known signing limitation

If BRENDIGO LTD trusted code-signing secrets are not configured, 0.1.1 Beta Windows executables are published unsigned and Windows may show Unknown Publisher/SmartScreen warnings. Ghost FTP does not disable or bypass those operating-system protections. A trusted publisher experience requires a valid CA-issued code-signing certificate.
