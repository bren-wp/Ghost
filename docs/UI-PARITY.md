# Ghost FTP desktop UI parity contract

Ghost FTP **0.1.3 Beta** is one desktop product with native Windows and Linux renderers. This document defines the visual/workflow contract that prevents the two implementations from drifting into separate products.

## Authentic reference

The canonical repository image is the real compiled Windows client at **1914 × 907** logical pixels / 96 DPI:

```text
assets/readme/ghostftp-client.png
```

The image must be generated by the real application capture path, not substituted with a mockup.

## Shared workstation hierarchy

Both **Windows and Linux** must preserve this hierarchy:

1. product/sidebar identity;
2. menu and primary toolbar;
3. Connection Log and Quick Connect;
4. Local and Remote panes;
5. Transfers queue;
6. status, diagnostics, Site Manager and Settings.

The exact native control implementation may differ, but the user-facing information architecture and operation order must remain recognizable as the same Ghost FTP product.

## Canonical palette

`GhostReferencePalette` is the authoritative dark-workstation palette. Windows WPF, Windows Setup and Linux X11/XWayland rendering should consume equivalent palette values so surfaces do not drift.

Key characteristics:

- dark blue-black workspace rather than flat black;
- restrained blue borders;
- violet accent for primary actions/focus;
- clear success/danger state colors;
- compact radii and workstation density;
- readable muted text without washing out secondary information.

## Resizing

Windows provides native window maximize/minimize/restore plus internal splitters for the sidebar, top connection area, Local/Remote panes and Transfers queue. Layout state is persisted locally.

Linux responds to native X11/XWayland window resize and uses the same logical proportions. Narrow-width rendering may hide secondary labels/buttons before removing primary file-transfer actions.

## Quick Connect parity

Both renderers expose:

- Host;
- Port;
- Security;
- Username;
- Password;
- connect/disconnect;
- session-only behavior;
- saved-site integration;
- FTPS Explicit recommendation.

Credentials must not be logged. Plain FTP requires an explicit warning/approval boundary for non-Demo connections.

## Local / Remote parity

Both panes provide:

- current path;
- Up/Home navigation;
- file/folder listing;
- upload or download primary action;
- refresh;
- new folder;
- rename;
- delete;
- filtering/search behavior;
- selection state;
- double-click navigation/file action behavior.

Contextual Local/Remote file operations should not be redundantly duplicated as unrelated global toolbar actions.

## Transfer queue and cancellation

Windows and Linux share the same `TransferQueueService`, including the same bounded worker/concurrency/retry/cancellation model. The **transfer queue and cancellation** semantics are therefore a product contract rather than renderer-specific behavior.

0.1.3 parity includes:

- queued/running/retrying/completed/failed/cancelled state;
- queue-level pause/resume of new dispatch;
- retry failed;
- selected/all cancellation;
- cleanup of finished history;
- selected transfer rows;
- progress/speed display where width permits.

Running transfers continue when the queue is paused. Neither renderer may label this as suspension of the active FTP byte stream.

Windows additionally exposes a richer transfer context menu for selective completed/failed/cancelled cleanup and source/destination path copy. Linux exposes the same Core state and the most important queue controls directly in the native transfer header; renderer-specific affordances may differ where native UI constraints differ.

## Site Manager parity

Saved sites remain local on both platforms. Both renderers show server identity/security details and can create/select/delete local profiles. Saved passwords are opt-in and protected with the platform-local mechanism.

## Settings parity

Both platforms expose or consume the same underlying settings for language, theme/appearance, retries, concurrent transfers, connection/command/transfer timeouts, keepalive and local workspace state.

English is the primary/fallback language. The 29-language catalog is shared.

## Status and diagnostics

Connection state must distinguish:

- offline;
- connecting;
- connected TLS;
- connected plain FTP;
- local Demo;
- connection failure/loss.

Diagnostics must remain local/user-initiated and must not turn into hidden telemetry.

## UI cleanup rules

- Keep primary actions visible before secondary diagnostics/actions.
- Do not overlap toolbar/search/language controls at compact widths.
- Use consistent row heights, borders, focus and selected states.
- Avoid excessive nested card styling.
- Do not restore duplicated file-operation controls removed from the 0.1.2 workstation cleanup.
- Keep transfer-management state visible without making the transfer panel dominate the workspace.

## Setup parity with product visual language

Windows Setup is not a Linux component, but it must look like the same Ghost FTP product: same identity, palette, typography, compact button treatment, privacy wording and Beta/version identity.

## Parity verification

CI builds both renderers and runs real Windows WPF / Linux X11 smoke paths. The Windows capture path produces the canonical 1914 × 907 reference image. Source audit requires both native renderers and the shared design/protocol components to remain present.
